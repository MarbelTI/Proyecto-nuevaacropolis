2. QUÉ ES EL SISTEMA Y CÓMO ESTÁ HECHO
===============================================================================

Nombre visible: Mnemósine
Nombre interno: SISFIA (así nació el proyecto)

IMPORTANTE: el nombre visible puede volver a cambiar. Por eso vive en UN SOLO
archivo: src/lib/branding.ts. Se cambia ahí y queda cambiado en toda la app.

NO renombrar nada interno. Las claves de localStorage empiezan por "sisfia_";
si se renombran, todos los usuarios pierden sus datos locales.

Stack:
  - TanStack Start (createServerFn / useServerFn) + TanStack Router
  - React 19, TypeScript estricto
  - Tailwind CSS v4 + shadcn/ui
  - Supabase: Auth, Postgres con RLS, funciones SECURITY DEFINER
  - SheetJS (xlsx) para importar y exportar Excel
  - Despliegue: Vercel, automático en cada push a main

Dónde viven los datos HOY:
  - Transacciones, tasas BCV, alumnos  -> localStorage + sincronización manual
                                          a Supabase (botón "Subir a nube")
  - Asistencias y reflexiones          -> SOLO localStorage. No hay sync todavía.

Los correos en las migraciones se guardan como hash md5, nunca en texto plano.

7. LA PLANTILLA DE MANUELA — ANÁLISIS Y PLAN DE CONCILIACIÓN
===============================================================================

Archivo analizado: PLANTILLA SISTEMATIZADA ECONOMIA.xlsx
Este es el modelo de informe que ella entrega. Los próximos serán parecidos.

TIENE TRES HOJAS:

  "PLANTILLA SISTEMATIZADA ECONOM "
     Padrón de miembros agrupado por aula (KRISHNA I MARTES, etc.)
     Columnas: NOMBRE / CEDULA / TELEFONO / CUMPLEAÑOS / INGRESO / REC.MIEMBRO
     63 personas, 46 cédulas, 60 teléfonos. Sirve para cruzar con Solvencias.

  "ECONOMIA DICIEMBRE24"   <-- ESTA ES LA DE LA CONCILIACIÓN
     La fila 1 tiene los nombres de categoría como ENCABEZADOS DE COLUMNA,
     y los montos individuales van listados hacia abajo en cada columna.
     Categorías vistas: MIEMBROS, PROBAS, INTERESES PTAMO, VETERINARA,
     CLASE, FILOART, RECITAL, MTC, CENA, FRANELAS, PROFESOR, ALQUI,
     MILAGRO ELENEA, ELECTRIC, HIDRO, PUBLICIDAD, MANTENIMI, INTERNET.

  "Hoja1"
     Hoja de trabajo: libro diario (Fecha, Descripción, Monto, Moneda, Tasa,
     Total Usd), un bloque de solvencias (Nombre, Meses Pagados, Abonos,
     Saldo Pendiente USD) y las tasas BCV.

EL HALLAZGO CLAVE
  Nuestro export de "Resumen Mensual" YA usa esa misma estructura: categorías
  como columnas, montos hacia abajo. Eso hace la conciliación casi directa.

CÓMO SERÍA LA CONCILIACIÓN
  1. Cargar su hoja "ECONOMIA <MES><AÑO>".
  2. Sumar cada columna de su hoja.
  3. Sumar cada categoría nuestra del mismo mes.
  4. Mostrar una tabla comparativa: categoría / lo de ella / lo nuestro /
     diferencia, con las diferencias resaltadas.

DOS DETALLES A RESOLVER AL CONSTRUIRLO
  a) Ella pone los egresos en columnas aparte (ALQUI, ELECTRIC...) SIN signo
     negativo. Nosotros los guardamos negativos. Hay que comparar por valor
     absoluto por categoría, no sumas globales.

  b) Sus nombres de categoría vienen abreviados: ALQUI, MANTENIMI, ELECTRIC.
     Hay que mapearlos a nuestras categorías UNA VEZ y guardar ese mapa, para
     que ella no tenga que cambiar su forma de trabajar.

9. OPERACIÓN DEL DÍA A DÍA
===============================================================================

Ver la app en local:      npm run dev
Compilar para verificar:  npm run build
Subir a producción:       git push   (Vercel despliega solo, ~1 minuto)

Correr una migración: se pega el contenido del .sql en el editor SQL de
Supabase y se ejecuta. Las migraciones están escritas para poder correrse
más de una vez sin romper nada.

Rama de trabajo: main. Todo está subido y sincronizado con GitHub.
